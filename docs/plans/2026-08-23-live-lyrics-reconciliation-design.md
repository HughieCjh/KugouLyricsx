# KugouLyricsx 实时歌词校准设计

## 方案

问题不是统一时间偏移，而是歌词来源和时间语义同时失真。《你》的当前媒体时长约为 282.8 秒，标题命中的 KRC 最后一行却在约 168.1 秒结束；文件开头还包含被定时编码的歌名和制作人员信息。旧实现只按标题选择最新 KRC、把所有定时行都视作歌词，并让每行持续到下一行开始，因此会显示酷狗界面已经过滤的内容，也会在间奏和长尾阶段保留旧歌词。

采用混合来源策略。新增一个有状态的实时歌词检测器，观察酷狗发布到 macOS 媒体 `artist` 字段的文本：如果它与任一本地歌词行相符，或在同一首歌中连续变化，则把该字段识别为酷狗实时歌词。识别成功后以它为最高优先级；空文本代表间奏，应在 Touch Bar 留空。稳定不变的正常歌手名不会立即被当作歌词。

KRC 继续作为回退来源，但解析时移除标题、歌手、制作信息和极短的伪定时行，保存每行的持续时间与结束时间。时间轴在一行结束且下一行尚未开始时返回空，不再保持旧歌词。本地歌词最后结束时间与媒体时长差异过大时，标记为不兼容，不允许直接显示；它仍可用于识别酷狗实时歌词。在线回退继续保留，但错误歌词优先级低于“等待歌词”。

验证覆盖当前实测数据、制作信息过滤、间奏空白、实时字段识别、稳定歌手名不误判、拖动进度条和暂停/切歌的既有回归测试。发布为 v0.3.1（构建号 10），更新 README 后重新生成 App、DMG 和 ZIP。
